## Для чего это приложение?

В некоторых странах Telegram заблокирован, замедлен или просто не
подключается. Обычный способ обойти это — **прокси**: другой компьютер,
где-то в другой стране, который передаёт ваш трафик Telegram за вас.

У Telegram есть свой тип прокси — **MTProto**. Люди выкладывают такие прокси
публично, списками и в каналах, бесплатно.

Проблема в том, что **эти списки очень быстро устаревают**. Прокси, который
работал утром, к вечеру уже мёртв — его перегружают, блокируют или просто
выключают. Большинство адресов в любом публичном списке уже не работают к
тому моменту, как вы их нашли. Перебирать их вручную — долго и утомительно.

**Nimku Proxy делает эту работу за вас.** Приложение собирает адреса прокси
из множества публичных списков, проверяет каждый и показывает только те,
которые работают **прямо сейчас** — самые быстрые сверху. Вы нажимаете на
один из них и подключаетесь.

Приложение **полностью бесплатное**. Без оплаты, без подписки, без аккаунта,
без регистрации, без рекламы.

## Чем это приложение **не** является

Чтобы вы понимали, что именно устанавливаете:

- **Это не VPN.** Приложение не пропускает через себя трафик вашего телефона.
  Оно находит адреса прокси и передаёт выбранный вами в Telegram. Прокси
  использует только Telegram — браузер и другие приложения работают как
  обычно.
- **Оно не подключается к Telegram за вас.** Оно не трогает ваш аккаунт,
  переписку и номер телефона. Оно никогда не просит войти в аккаунт.
- **Оно ничего о вас не собирает.** Ни аккаунта, ни аналитики, ни трекеров,
  ни рекламы. Подробнее — в разделе [Приватность](#приватность).

## Как это работает

```
  1. Сбор             2. Проверка          3. Показ            4. Подключение
  ───────             ───────────          ────────            ─────────────
  Адреса прокси       К каждому адресу     В списке только     Открывается
  из множества     →  реально             →  рабочие, самые →  Telegram и
  публичных списков   подключаемся           быстрые сверху     спрашивает вас
```

Главное здесь — шаг 2. В публичных списках прокси часто помечены как
«проверенные», но это было правдой на момент составления списка — возможно,
несколько дней назад. Nimku Proxy не верит таким пометкам и сам выполняет
настоящее MTProto-рукопожатие с каждым адресом — сейчас, с вашего телефона и
из вашей сети. Прокси, который не отвечает, в результатах не появится.

Эта деталь важнее, чем кажется: прокси работает или нет именно **из вашей
сети**. Тот, что прекрасно работает в одной стране, может быть заблокирован в
другой. Проверка идёт на вашем устройстве, поэтому результат верен именно для
вас.

## Установка

Android не разрешает устанавливать приложения не из Google Play, пока вы это
не разрешите, а некоторые производители добавляют дополнительные шаги. Так
происходит с любым приложением вне Play Store — дело не в этом приложении.

### Обычный Android (8.0 и новее)

1. Скачайте `NimkuProxy.apk` из
   [последнего релиза](https://github.com/nimku/mtproxy-finder-app/releases/latest).
2. Откройте скачанный файл. Android сообщит, что вашему браузеру (или
   Telegram, или файловому менеджеру) не разрешено устанавливать приложения.
3. Нажмите **Настройки** → включите **Разрешить установку из этого
   источника** → вернитесь назад → **Установить**.

Разрешение действует только для этого одного приложения — разрешив браузеру,
вы не разрешаете ничего другого.

### Xiaomi / Redmi / POCO (MIUI, HyperOS)

Здесь больше всего дополнительных шагов, и обычно именно тут люди сдаются:

- Настройки → **Защита конфиденциальности** → **Особые разрешения** →
  **Установка неизвестных приложений** → выберите браузер → включите.
- MIUI проводит собственную проверку и показывает большое пугающее
  предупреждение. Выберите **Всё равно установить**.
- Если всё равно не устанавливается: Настройки → Защита конфиденциальности →
  отключите **Повышенную безопасность** (**Enhanced security**). Пока она
  включена, MIUI молча блокирует установку. После установки её можно включить
  обратно.
- Некоторые версии MIUI требуют войти в Mi-аккаунт и иметь интернет, чтобы
  завершить установку. Это требование MIUI, а не приложения.

### Huawei / Honor (EMUI, HarmonyOS)

- Настройки → **Безопасность** → **Дополнительные настройки** → **Установка
  приложений из внешних источников** → разрешите браузеру или файловому
  менеджеру.
- Если включён Pure Mode, он не пропустит ничего, кроме AppGallery:
  Настройки → Безопасность → **Дополнительные настройки** → **Pure Mode** →
  выключить.

### Samsung (One UI)

- Настройки → **Приложения** → выберите браузер → **Установка неизвестных
  приложений** → разрешить.
- В One UI 6.0 и новее есть **Auto Blocker**, который полностью запрещает
  установку со стороны: Настройки → **Безопасность и конфиденциальность** →
  **Auto Blocker** → выключить.

### Если телефон не разрешает вообще

Некоторые телефоны от операторов и корпоративные устройства действительно не
позволяют устанавливать сторонние приложения. Тогда установите с компьютера
по USB:

```bash
adb install NimkuProxy.apk
```

## Как пользоваться

### Первый запуск

1. Откройте приложение. Настраивать нечего: ни входа, ни ключа, ни регистрации.
2. Выберите **профиль сети** — Авто, Wi-Fi или LTE. Оставьте **Авто**, если
   нет причин менять: приложение само подберёт параметры проверки под ваше
   соединение.
3. Выберите **глубину сканирования**:
   - **Быстрое** — беглый проход, для повседневного использования достаточно.
     Начните с него.
   - **Сбалансированное** — больше адресов, всё ещё довольно быстро.
   - **Полное** — проверяет всё собранное, до 15 000 адресов. Долго, но
     тщательно. Используйте, когда быстрое сканирование ничего не находит.
   - **Своё** — ваши собственные настройки.
4. Запустите. Результаты появляются **прямо во время сканирования** — ждать
   его окончания не нужно. Самые быстрые прокси поднимаются наверх.

### Подключение к прокси

1. Нажмите на прокси в списке.
2. Откроется Telegram и спросит, включить ли этот прокси.
3. Подтвердите. Telegram теперь идёт через него.

Если позже он перестанет работать — прокси умирают постоянно — просто
откройте Nimku Proxy, просканируйте снова и выберите другой.

### Что ещё умеет приложение

- **Избранное** — отмечайте звёздочкой прокси, которые вам хорошо работают.
  Приложение может тихо проверять их в фоне и уведомлять, когда какой-то
  перестал работать.
- **История и статистика** — видно, какие источники реально дают рабочие
  прокси именно в вашей сети, а какие бесполезны.
- **QR-коды** — показать прокси QR-кодом, чтобы передать человеку рядом, или
  считать чужой с фотографии.
- **Экспорт списка** — сохранить рабочие прокси в файл.
- **Свой источник** — если знаете список, которого нет в приложении, добавьте
  его HTTPS-адрес в настройках.
- **Оформление** — темы, цвета, скругление углов, размер текста и язык
  интерфейса.

## Если у вас не открывается GitHub

Обычно приложение берёт списки прокси с GitHub, а если он недоступен —
с нескольких зеркал. В некоторых регионах сам GitHub недоступен, причём это
различается по городам и даже по операторам внутри одной страны. Если
сканирование вообще ничего не находит — скорее всего, причина именно в этом:
приложение просто не может получить списки.

**Есть второй путь, которому GitHub не нужен совсем:**

1. Откройте наш бот в Telegram и попросите актуальный список прокси. Бот
   пришлёт вам обычный файл.
2. Нажмите на этот файл прямо в Telegram.
3. Выберите **Открыть с помощью → Nimku Proxy** (на некоторых телефонах это
   «Открыть в…» или меню «Поделиться»).
4. Приложение прочитает список и проверит его точно так же, как при обычном
   сканировании.

Также можно переслать сообщение со ссылками на прокси и поделиться им в Nimku
Proxy, либо сохранить любой список в файл `.txt` и открыть его в приложении
через **Проверку файла**.

Telegram обычно продолжает работать, когда GitHub недоступен — именно поэтому
в таком случае список идёт через Telegram.

## Безопасно ли это устанавливать?

Не стоит устанавливать незнакомый APK просто потому, что вам так сказали, и
верить нам на слово тоже не нужно. Проверить можно несколькими способами — от
самого простого к самому надёжному.

### Проверьте файл сами

Загрузите APK на сервис вроде VirusTotal или проверьте любым антивирусом,
которому доверяете. К каждому релизу приложен файл `.sha256` — это значение
можно вставить в поиск VirusTotal и сразу найти отчёт по файлу.

Учтите: антивирусы иногда помечают прокси- и сетевые приложения по
эвристике. Если один-два сканера что-то нашли, а все остальные — нет, это
почти всегда ложное срабатывание, а не реальная находка.

### Проверьте, что файл не подменили

В каждом релизе рядом с APK лежит файл `.sha256`. Сравните:

```bash
sha256sum NimkuProxy-v2.0.0.apk
```

Если значение совпало — ваш файл побайтово тот же, что был опубликован.

### Проверьте, кто его подписал

Это самая надёжная проверка, и особенно полезная при обновлениях. Все релизы
подписаны одним и тем же ключом, поэтому изменённая или пересобранная копия
это значение повторить не сможет:

```bash
apksigner verify --print-certs NimkuProxy-v2.0.0.apk
```

Ожидаемый результат:

```
Signer #1 certificate SHA-256 digest: d205a5af6051d2d29b418c6094aa8da760e5fbb05f128bf031d9890f138fad96
```

Владелец сертификата: `CN=Nimku Proxy, O=Nimku, C=US`. Встроенный
автообновлятор приложения выполняет ровно ту же проверку перед установкой
обновления, поэтому подменить ключ незаметно невозможно.

### Соберите приложение сами и сравните

Самый исчерпывающий ответ на вопрос «что внутри этого файла» — собрать его из
исходного кода в этом репозитории и сравнить:

```bash
git clone https://github.com/nimku/mtproxy-finder-app
cd mtproxy-finder-app
git checkout v2.0.0
./gradlew --no-daemon assembleRelease
```

Без ключей подписи получится **неподписанный** APK по пути
`app/build/outputs/apk/release/app-release-unsigned.apk`. Сравните его
скомпилированный код с опубликованным, не считая файлов подписи, которые
совпасть не могут по определению:

```bash
mkdir -p built published
unzip -q -o app/build/outputs/apk/release/app-release-unsigned.apk -d built
unzip -q -o NimkuProxy-v2.0.0.apk -d published
sha256sum built/classes*.dex published/classes*.dex
diff -r -x 'META-INF*' built published
```

Значимо здесь сравнение `classes*.dex` — это и есть код программы.

Чтобы получить такую же сборку, нужны те же инструменты, что и в CI:
**JDK 17** (Temurin), **Android SDK 35**, **Gradle 8.9** (обёртка есть в
репозитории), **AGP 8.7.3**, **Kotlin 2.0.21**. Другая версия JDK или плагина
даст другую, но столь же корректную сборку.

Честно о пределах этого метода: инструменты Android не гарантируют побайтово
одинаковый результат на разных машинах, поэтому небольшие расхождения в
порядке файлов или временных метках — это норма, а не признак подмены.
Криптографически происхождение сборки доказывает именно проверка сертификата
подписи выше.

## Приватность

- Ни рекламы, ни аналитики, ни трекеров, ни сервисов Google и Firebase
- Ни аккаунта, ни входа, ни оплаты — о вас ничего не собирается и никуда не
  отправляется
- Приложение обращается только к публичным спискам прокси и к установленному
  у вас Telegram. Больше ни к чему.
- Результаты сканирования и избранное остаются на вашем телефоне
- Источники, которые вы добавляете сами, обязаны использовать HTTPS и
  проверяются перед использованием, чтобы вредоносный адрес не смог заставить
  приложение сканировать вашу домашнюю сеть
- Обновления проверяются по версии, имени пакета, сертификату подписи и
  SHA-256 до установки

Одно честное предупреждение: **публичные прокси держат незнакомые вам люди.**
Владелец прокси видит, что вы подключаетесь, и объём вашего трафика. Ваша
переписка в Telegram остаётся зашифрованной между вами и Telegram, а секретные
чаты — сквозным шифрованием, но прокси не является средством анонимности и не
заменяет шифрование. Используйте его, чтобы получить доступ к Telegram, когда
он заблокирован, а не чтобы скрыть, кто вы.

## Тем, кто уже платил

Версии до 2.0 требовали платную подписку. Её больше нет совсем — начиная с
2.0 приложение вообще не проверяет лицензию и ничего не спрашивает. Если вы
остались на старой версии, для неё включён бесплатный режим для всех, так что
она продолжит работать, даже если вы никогда не обновитесь.

## Откуда берутся прокси

Приложение использует публичные списки прокси, которые ведут несколько
открытых проектов; все они перечислены в
[`sources_manifest.json`](sources_manifest.json). Дубликаты удаляются, а
затем каждый адрес приложение проверяет само — пометке «проверено» из списка
оно не доверяет.

## Для разработчиков

### Сборка

Нужны JDK 17 и Android SDK 35.

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Структура исходников:

```text
core/       константы и общие утилиты
domain/     модели, парсер, источники, агрегатор
data/       сеть, Room, DataStore, экспорт
ui/         Jetpack Compose + Material 3
updater/    загрузка и проверка обновлений
work/       фоновые проверки и задачи обновления
```

### Содержимое репозитория

| Путь | Что это |
|---|---|
| `app/` | Android-приложение (Kotlin, Jetpack Compose, Material 3) |
| `sources_manifest.json` | Список публичных источников прокси |
| `.github/workflows/mirror-proxy-feeds.yml` | Задача, зеркалирующая источники в `proxy-feeds/` |
| `update_manifest.json` | Запасные данные об обновлении, если GitHub API заблокирован |
| `license/status.json` | Наследие — нужно только для работы установок до 2.0 |
| `exteragram/` | Необязательный плагин для клиента exteraGram |

### Подпись релиза

`assembleRelease` подписывается только если заданы переменные окружения
`RELEASE_KEYSTORE_PATH`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS` и
`RELEASE_KEY_PASSWORD` (см. `app/build.gradle.kts`) — без них сборка всё равно
пройдёт, но APK будет неподписанным. В CI `.github/workflows/release.yml`
читает соответствующие секреты GitHub Actions (`RELEASE_KEYSTORE_BASE64`
вместо `_PATH`). Само хранилище ключей в репозиторий никогда не попадает.

### Отправка на VirusTotal

Workflow релиза умеет автоматически загружать каждый APK на VirusTotal и
класть ссылку на отчёт в описание релиза. Для этого нужен секрет репозитория
`VIRUSTOTAL_API_KEY` (бесплатного ключа достаточно). Без секрета релиз всё
равно выйдет и ссылку напечатает — просто без загрузки, так что отчёт
появится только после того, как файл проверит кто-то сам.
